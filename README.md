# Lovomo

**简体中文** · [English](README.en.md)

> 仓库地址：<https://github.com/slpk1ng/Lovomo>

基于本地大语言模型（LLM）与 GPT‑SoVITS 语音合成技术的 AI 角色聊天助手。支持接入 NapCat 连接 QQ（另有 QQ 官方机器人与微信 ClawBot 两种接入方式），提供全功能的 WebUI 管理控制台。代码按职责拆分为 `modules/` 下的功能模块。**接入方式**在左侧栏单独一页：一个平台一条通道，微信与 QQ 官方机器人扫码登录（登录态、收消息游标与会话令牌随连接保存），角色可绑定某一条连接；消息按会话走"它从哪条通道来的"那条连接，重启后仍然记得，没记过的会话按目标格式（微信 openid / 群聊 @chatroom）认出平台再选连接（所以定时任务、主动消息、节日问候、日记在微信/QQ 官方上同样能发出去，不会落到默认的 NapCat 上报「无法获取用户信息」）；微信这条通道能收文字与图片（图片自动下载解密后交给识图），收不到回复时可以点「投递自检」区分"服务端收下了"与"真的投递到微信了"。

## ✨ 功能特性

* **本地化运行**：数据不经过外部服务器，保障隐私安全。
* **AI 语音交互**：通过 GPT‑SoVITS 实现文本到语音的拟真合成，也可切换到云端 TTS 服务（OpenAI 兼容接口或阿里云百炼），并可为每个情绪单独指定音色（模型与音色需配套），支持用一段文字描述设计专属音色，或上传一段或多段音频复刻音色。合成前会剔除非台词内容（`tts_strip_non_dialogue`，默认开启）：括号里的动作、表情与场景说明（如 (笑)、[旁白]）以及颜文字只留在消息文本里，TTS 只念台词，日志会写明剔除了哪些。回复也不必每条都配语音：「语音发送方式」可选每条都发、按概率发或只在私聊发。
* **情绪模拟**：支持多情绪切换、语气渐变、呼吸间隙与交叉淡化，让语音更自然。
* **角色定制**：可通过 WebUI 轻松设置角色人格、回复风格与提示词。
* **聊天管理**：支持多会话管理、历史记录查看与一键删除；回复可按语境引用当前消息，用户要求时还能直接@本会话发过言的群成员，且@出现在话里该出现的位置，不会一律顶在消息最前面；@一律是真实的@（台词里两个 @ 连着写（「@@某人」「@@QQ号」「@@所有人」）会被还原成真正的@，单个 @ 一律当普通文字，被@的人才会收到提醒，且@与后面的文字之间留一个空格）；开启「分开发送」时聊天记录按实际发出的每条消息分别记录，不同用户的气泡用不同颜色区分；记录弹窗按会话单独放大；头像用 QQ 真人头像并紧跟昵称，微信这类取不到头像的会话不显示头像、消息一律绿色气泡（不再按发言者换色）。
* **戳一戳、撤回与转发消息**：角色能感知被戳一戳并按被戳的反应回应，也会在聊天里主动戳对方，戳一戳走真实的戳一戳交互（不再只是发一句「戳了戳你」的文字）；说错话时会把这条回复撤回，也可以故意发出来让你看一眼再撤掉，你明确让她撤回时也会真的撤回（只认你自己打的字，引用或转发内容里提到「撤回」不会被当成要求；引用某条消息让她撤回，撤的就是被引用的那一条，连同它同一句话的语音一起撤，「你还没撤回呀」这类催促也认；群管理员或群主还能让她撤回别人的消息，一般群成员叫不动她删别人的消息）；转发过来的聊天记录会先读取内容再回复；她还能自己决定这条回复怎么发出去（照常带语音、只发文字，或按主人要求一个字一条消息地发，也不会因为发送形态出现在后面的句子上就丢掉这之后的句子）；只能收发文字的接入方式（微信、QQ 官方机器人）下，提示词不会教她做这条通道根本做不到的@、引用、戳一戳、撤回；默认丛雨人设补充了「说话方式」要求，回复更口语、更抓细节、更主动，也更少助手腔。
* **日志监控**：实时查看运行日志，每行统一以 `[时:分:秒.毫秒][来源][级别]` 开头（来源为 `Lovomo` 或 `插件`，级别为 `INFO` / `WARN` / `ERROR`，级别名不带方括号），并按级别着色（时间绿色不加粗，INFO 行白色、WARN 行黄色、ERROR 行红色），方便排查问题。
* **关窗即释放**：窗口收进托盘后自动释放界面进程（约 300MB 交还系统），再次打开时自动重建，约 0.5 秒回到底。

### 🧩 扩展功能（全部可在 WebUI 中独立开关与配置）

* **定时任务与主动消息**：自定义间隔 / 每日 / 每周问候任务；长时间未互动时主动找话题；节日、纪念日与用户生日自动祝福；程序在问候时间之后才启动时自动补发当天漏掉的问候（可关）；静默时段与每日上限防打扰。
* **待办提醒**：聊天中说「提醒我…」自动创建（正则或 LLM 提取），到点自动发送提醒，WebUI 可视化管理。提醒话术可用 LLM 按角色人设现场生成（默认）或使用固定模板；LLM 失败/漏说事项时自动回退模板，不漏提醒。程序没开而错过的提醒会在重新上线后补发一次；发送失败（接入方式掉线等）的提醒会自动退避重试几次，连续发不出去才标为「已过期」，不会一直挂着不响。
* **会话回忆**：角色会记得更早聊过的细节 —— 「还没结清的事」每轮置顶（说好要去海边但还没出发，不会聊到别处就忘），并按当前话题从历史里检索相关往事注入（同一话题时段只取一段，结果按时间从早到晚排列）；检索方式可选语义（embedding）或字符重合（lexical，零依赖、离线可用），嵌入不可用时自动退回字符重合。
* **实时流式回复**：边生成边逐句合成发送，大幅降低首句等待时间；生成失败时回一条中文提醒并说明可能原因（原始报错只留在日志里，也不会被合成语音），不再只回一句「出错了」。
* **表情包**：按情绪目录分类的本地表情图，回复时按概率附带；识图时若 LLM 判定图片有趣/值得收藏可自动存入对应情绪分类，后续相同情绪回复按概率发出（收藏判定搭车在识图调用内完成；分类与命名另走一次不带人设与心情的中立调用，避免被角色当时的情绪带偏）。「选择图片」旁的「一键识别」可批量把图片或整个文件夹交给识图模型：逐张判断该放进哪个情绪分类并给出通用命名，然后自动归档到「表情包目录」对应文件夹（分类名沿用收藏那套清洗规则，不会乱建目录）。
* **多角色对话**：每个角色拥有独立人设与语音（未填写提示词的角色不会套用默认角色的人设）；群聊中 @ 机器人后，按消息中出现的角色名路由回复，支持角色间互相接话（群聊默认需要 @ 才响应，可用 `group_need_at` 关闭；引用机器人消息视同 @），并区分发言者、引用消息与被@成员；群聊上下文按成员分别标注，不将他人话语归到当前发言者，且标注编号按完整历史分配，开了「对话自动摘要」截断上下文后也不会与当前发言者错位；群聊中已确立的关系与称呼按完整历史记忆，长对话后也不会被其他成员的追问、自称或冒名顶替改口。
* **工具调用 (Function Calling)**：内置时间 / 计算 / 天气 / 网页读取，支持自定义 HTTP 与命令工具；每个工具可独立授权（用户白名单、调用上限）。
* **知识库 RAG**：上传文档自动分块向量化（本地向量库，无外部依赖），回答时自动检索注入。
* **用户画像**：按 QQ 记录昵称、生日、喜好，支持 LLM 自动提取与生日自动祝福；昵称默认取对方的 QQ 昵称，之后不会被自动提取改写，只有用户自己要求你改称呼（或手动在 WebUI 修改）才会变；自动提取的删除类字段有单次上限（最多删掉某一类的一半），避免一次误判把画像整个清空。
* **关系进度（Galgame 式攻略）**：按「角色 × 用户」记录好感与关系性质，好感只随长期相处缓慢累积（每人每天有上限），代表熟悉程度（陌生 → 认识 → 朋友 → 挚友）；「暧昧」「恋人」由相处里是否真的出现恋爱意味决定 —— 只是一直聊天、并不暧昧的关系好感再高也不会被算成恋爱，单纯喊老婆/老公这类称呼不会让关系前进，含糊的「我答应你」也不算确认交往（她答应的可能是别的事），只有回复里真的把关系说定才会记为伴侣，答不答应告白、要不要角色自己先开口都由角色自己决定；关系也能退回去 —— 对方明确说分手/绝交（或她自己把关系说断）时解除关系，好感保留（它代表熟悉程度，分手不会让两个人变回陌生人），而且这类消息一定会让她自己回应，不会被心情概率挡掉；关系还没走到「暧昧」之前她不调情、不说带性暗示的话、也不主动撩人 —— 人设里「爱调情」「嘴上不正经」那类描述要等关系到了才适用，所以刚认识不会被直接带进暧昧；攻略难度分简单 / 普通 / 困难 / 极难四档（默认普通），它不只决定好感涨得多快，也决定角色有多独立自洽 —— 难度越高，她越有自己的目标、底线、执念与拒绝权，礼物、情话与长时间陪伴换不走她的心，需要理解她的过去、尊重她的底线、在关键节点做出符合她逻辑的选择，也可能到最后也没有选择你；能定关系的最早关系性质、伴侣人数上限（默认不限）与每天好感上限都可配；关系越近角色越主动（阶段解锁），久不互动好感会慢慢流失，提到别的角色会吃醋，伴侣纪念日角色会主动祝贺，「用户画像」页可查看每位用户当前关系进度、好感与在一起天数。
* **陪伴玩法**：每天按概率由角色自己现场想一件随机奇遇，之后在对话里自然聊起；角色在对话里答应的事会被记下来，隔天由每日陪伴检查主动兑现（冷落流失、纪念日祝贺也在这次检查里执行，时刻可配）。
* **动态上下文**：对话自动摘要 + 话题检测，长对话不降智；摘要更新后还会拿整段对话再复核一次关系确认、用户画像与词条（只补空缺与漏判，每个会话最多 10 分钟一次）；摘要里混进的角色台词会被单独剔除，不会因为一句台词让整段背景作废（更早的对话不会丢）。
* **统计面板**：消息量、情绪分布与趋势图表，LLM/TTS 耗时实时监控；另有心情/好感历史曲线与每日心情日记，曲线可按时间区间筛选，「今天 / 昨天」还能按小时查看并下钻到分钟。
* **情绪音频管理**：WebUI 上传 / 试听各情绪的参考音频，逐段填写参考文字（可用一键语音识别自动生成），一键规整时长，一键新建或删除情绪。同一套语音识别设置也用于用户发来的语音：对方发语音时先转成文字再回复（引擎、语种、模型都在「配置文件 → 更多 → 语音识别」里配）。
* **数据导入导出**：聊天记录（单个 / 全部打包）一键导出导入备份；配置可存成多份预设，随时一键切回。
* **回复审判与心情**：LLM 先判断消息是否需要回复再开口；角色拥有随对话增减的持久化心情值，心情值低时回复概率按配置降低（WebUI 可开关与调参），每轮还会朝初始值回稳一点（`mood_regress_rate`，默认 0.1，0 = 关闭，避免心情只加不减一路顶到上限），隔天的低心情每天会朝初始值自动回升（`mood_daily_recover`，默认 20），深夜走低、周末回暖、长期没人聊缓慢走低（只影响判定不落盘），每天还会按当天真实发生过的对话为每个会话写一篇角色口吻的心情日记并发出（错过检查会在启动时按天补写；日记只发出去，角色自己仍以为那是不给别人看的东西；要是写成把当天说过的话抄一遍，会判为偷懒重写，仍照抄就这天不写）。心情值还会直接影响说话风格：偏低转冷淡、低迷转烦躁并把回复压到 1~2 句（`mood_style_enabled`，默认开启）。群聊中心情值按用户隔离：某位用户惹角色不开心只会降低对该用户的回复意愿，不影响其他成员。角色说要去睡觉、玩游戏这类耗时较长的事后，普通消息可以选择不回应（点名召唤或刻意打扰仍会吵醒她）。
* **WebUI 聊天测试台与角色档案**：「聊天测试」页不开 QQ 就能直接和角色对话，走与真实消息完全相同的审判/心情/好感链路；配置页可把角色的人设、会话记忆、好感与心情记录打包导出成 JSON 档案，或导入档案（可覆盖同名角色）。界面快捷键：Ctrl+S 等同于「仅保存」，Esc 逐层返回（关弹窗 → 退出插件功能页/webui → 退回上一个页面）；配置保存结果就显示在右下角保存按钮上方，统计面板的折线图把鼠标停在某一列上会列出该列所有曲线的数值；心情日记、自主学习词条、用户画像等长列表按每页 10 条分页。界面中英双语，日志按级别着色（INFO 绿、WARN 黄、ERROR 红）。
* **工具误调防护**：消息不含任何工具触发词（时间/计算/天气/搜索/网址等）时不会进入工具调用流程，显著减少 LLM 乱调工具；触发词可在 WebUI 自行配置；问自己的提示词、之前聊过什么这类只有角色自己能答的问题不会再去联网搜索。
* **语音/文本分开发送分段**：分开发送时若 LLM 返回一整段未分句内容，会按 `。？！.!?` 自动切分后逐段合成语音与文字。
* **隐私保护**：可为 WebUI/聊天记录设置访问密码，另可再设一个**二级密码**，读取聊天记录、保存、导入导出、安装插件、删除、发布与下架等敏感操作要再输一次才能执行；删除会话时同步清理该会话的心情、心情日记、承诺、主动消息状态与**这个会话自己的关系进度**（关系按会话分开记，删掉会话它那条也跟着走，不会留在界面上继续往下算）；删私聊还会连这位用户的用户画像一起清空（当成从没聊过），群聊则不牵连成员各自在私聊里的关系与画像。
* **防刷屏**：同一会话短时间消息过多时自动忽略多余消息，避免重复占用 LLM 拖慢正常回复。
* **托盘常驻**：关闭窗口默认隐藏到系统托盘（窗口从屏幕和任务栏一并消失），托盘右键菜单提供「打开 Lovomo / 重启 Lovomo / 退出 Lovomo」；程序已在运行时再次双击 exe 只会把已有窗口唤到前台，不会起第二个进程。
* **检查更新**：定期从 GitHub 检查新版本，发现更新时在应用内弹窗提醒并显示该版本的更新内容（纯浏览器访问同样提示）；「插件 → 程序历史版本」可查看与下载历史 Release。
* **插件系统**：上传 `.zip` 或从在线市场一键安装插件，给程序加功能或换皮肤；插件可声明式生成设置界面，也可自带 HTML 功能页与独立的 `webui.html` 页面；安装前自动静态安全扫描，高危操作需显式确认；卸载时可选择保留插件配置与数据；作者还能把自己写的插件一键发布到 GitHub 市场仓库上架。

## 🚀 快速开始

### 直接安装

1. 下载最新的 `Lovomo_Setup.exe`。
2. 运行安装程序，选择安装路径并完成安装。
3. 双击桌面图标运行。

## 🖥️ WebUI 使用说明

程序启动后会自动打开控制台窗口（或通过浏览器访问 `http://127.0.0.1:11500`）。

* **配置文件**：设置 NapCat 地址、LLM 模型 API、TTS 服务地址、角色人格及情绪映射，以及各扩展功能的开关与参数；配置可存成预设随时切换（「切换预设」里可一键打开预设文件夹）。左侧锚点导航固定在侧栏右侧，配置表单在剩余空间里居中排布并自适应多列；每个配置项都是「标签单独一行、控件占满整行」的排布，多角色配置里的角色条目与「当前激活的角色标识符」各占一整行，互不并排。「当前激活的角色标识符」在多角色配置顶部；日常使用关系不大的开关集中在页面最底部的「更多」分组里：统计、软件更新、插件系统、音量统一、语音识别、防刷屏、隐藏高级 GSV 参数。插件市场用哪个仓库、分支前缀、来源清单与索引地址属于内部实现，不再出现在配置页上（需要时改 `config.json`）。
* **插件市场（测试版）**：上传 `.zip` 插件包、打开插件目录、刷新在线市场（官方 / 第三方），安装前自动做安全扫描；「发布到市场」也在这一页（在线市场之上）。官方市场读哪个仓库由 `config.json` 的 `plugin_market_repo` 决定（默认官方市场仓库，配置页不暴露），插件以目录形式提供 —— 市场仓库里一个插件一个 `plugins/<分类>/<插件id>/` 目录（分类取自插件清单的 `category`，缺省归入「其他」），条目记在 `plugins/index.json`（读的是仓库的默认分支）；工具栏可按分类筛选，每个分类后面跟着插件数量，与搜索、排序叠加。索引里没有条目时才回退去扫插件分支，分支列表按页拉全（超过 100 条也不会漏）。「来源清单路径」指向市场仓库里的一份清单（每行一个「用户名/仓库名」）时，官方市场还会把清单里这些仓库一起扫进来 —— 插件作者把清单加一行、提一个 Pull Request，合并后就上架了，不需要给仓库写权限。程序启动时在后台静默预取一次在线市场，进入该页即可直接看到列表，不占用启动时间、也不打断操作；点「刷新市场」才会强制重新拉取。
* **插件**：管理已安装插件（启用 / 停用 / 卸载，卸载时可选择保留配置与数据），卡片右上角可置顶，带功能页的插件点卡片即可进入设置，带 `webui.html` 的可以「打开webui」；侧栏「插件」右侧有折叠箭头，点一次展开带 `webui` 的插件名单、再点一次收起（切到其他页面也会自动收起）。这一页用满内容区宽度，一行三张卡片，四个操作按钮并排铺满整行。**新装的插件一律是停用状态**，由你自己到这一页点「启用」才会加载（覆盖升级沿用原来的开关，不会把用户的选择改掉）。页面右下角（内容块之外）的「检查插件更新」会去市场核对版本，列出有新版本的插件并可一键下载替换（覆盖安装，同样保留插件配置与数据）。一键发布把插件写进市场仓库的 `plugins/<分类>/<插件id>/` 目录（改过分类时旧目录一并删掉）、同步更新 `plugins/index.json`，并按白名单现场打成 zip 作为该版本 Release 的附件（下载量与收藏量就来自 Release），版本标签为 `<插件id>-v<版本>`；某个版本是否已上架按**当下的市场索引**（外加版本标签）判定，不读市场页那份 30 分钟缓存 —— 别人直接在 GitHub 上删掉插件，回到面板就会立刻看到它不再是已上架；本机发布 / 下架过的记录另存在 `publish_state.json`（重启仍生效、24 小时后作废），刚推上去或刚删掉的那几秒也算数。版本没往上走的插件不给发布按钮、改为提示「当前版本已发布过」（后端同样会拒掉不更高的版本，手工调接口也绕不过去）。已上架的插件那一行还有「下架」按钮：删掉市场里的分类目录、索引条目与该插件的全部版本标签和 Release。同一行只会给一个动作 —— 要么「发布」，要么「已发布过」+「下架」，不会两个按钮并排；发布 / 下架成功后面板立刻切到新状态（不等接口往返），推送期间「发布」按钮不可点，同一个版本不会被重复推。
* **聊天记录**：查看与管理所有会话，会话文件保留完整聊天记录，不再只留最近若干条；支持批量删除与导入导出；列表可切换排序 —— 按角色（同角色聚在一起，组与组之间、组内都按最新对话在前）、按最新对话、按最旧对话，后两者全局按时间排，不再按角色分组。角色回复在 QQ 里分成几条发出去，这里就记成几条；角色的气泡颜色固定，不同用户的气泡用不同颜色区分。
* **情绪音频**：可视化上传 / 试听各情绪的参考音频，逐段填写参考文字，一键规整时长与语音识别。
* **定时任务**：定时问候、节日 / 生日事件与待办提醒管理。
* **统计面板**：对话统计图表与实时性能监控。
* **高级功能**：表情包、工具调用、知识库 RAG、用户画像。
* **日志输出**：整页铺满内容区，实时查看系统运行状态，日志区右上角可勾选「显示完整日志」；每行日志统一为 `[时:分:秒.毫秒][来源][级别] 正文`（来源 `Lovomo` / `插件`，级别 `INFO` / `WARN` / `ERROR`），界面与 `app.log` 用同一套前缀；程序日志写入 `app.log`（程序目录，装到只读目录时为 `%LOCALAPPDATA%\Lovomo`），超过「日志文件大小上限」（默认 5 MB）时自动丢弃最早的记录。
* **使用教程**：内置图文教程，按「先配通、再调优、出问题怎么查」整理。
* **界面语言**：侧边栏左下角可切换「简体中文 / English」，界面文案与提示信息即时切换；选择会记住，刷新页面或重启程序后仍然生效。

## ⚙️ 配置说明

在 WebUI 中配置完成后点击「仅保存」（需要顺带重启 TTS 时用「保存并重启TTS」），程序会生成 `config.json` 文件并持久化设置；定时任务、工具、事件等数据分别保存在 `data/` 目录下的 JSON 文件中。**`config.json` 与 `data/` 固定存放在 `%LOCALAPPDATA%\Lovomo`**，不跟安装目录绑在一起 —— 换目录重装、覆盖升级都能接着用（老版本写在程序目录里的那份，首次启动会自动搬过去）；插件与发布记录同样在这个目录下。卸载时会逐项询问是否删除配置、聊天记录与插件，默认一律保留。

WebUI 的「LLM 服务地址」「识图模型服务地址」与「自定义请求体字段（JSON）」带有常见模型服务商预设，选中即可一键填入；识图模型与语言模型不是同一家服务商时，会额外显示「识图模型 API Key」，留空则沿用 LLM 的密钥。

### 核心配置项

|配置项|说明|
|-|-|
|napcat\_ws\_url|NapCat 的 WebSocket 地址|
|llm\_backend|LLM 后端类型：`ollama` 或 `openai`（LM Studio / llama.cpp 等 OpenAI 兼容服务）|
|llm\_base\_url|LLM 服务地址：Ollama 填 `http://127.0.0.1:11434`，LM Studio 填 `http://127.0.0.1:1234/v1`|

|tts\_backend|TTS 后端：`local`（本地 GPT‑SoVITS）或 `cloud`（云端 TTS）|

|ref\_audio\_root|参考音频根目录|
|model\_dir|TTS 模型文件夹|
|streaming\_enabled|实时流式回复开关|
|scheduler\_enabled|定时任务总开关|
|tools\_enabled|工具调用总开关|
|rag\_enabled|知识库 RAG 开关|
|profiles\_enabled|用户画像开关|

## ❓ 常见问题 (FAQ)

**Q：为什么窗口打不开？**
A：请确认已安装 Microsoft Edge WebView2 Runtime，或检查 `config.json` 中的 `webui\_port` 是否被占用。

**Q：主动消息 / 提醒话术偶尔不发送？**
A：生成的话术超过「主动消息/提醒话术字数上限」时，现在会按标点截断到上限内再发送，不再整段丢弃；只有整段没有任何标点时才丢弃。想让话术更长可以调大该上限。

**Q：升级或重新打包后，WebUI 还是旧界面？**
A：页面现在每次打开都会向服务端确认是否有更新，刷新即可生效；若仍是旧界面，请强制刷新一次（Ctrl+F5）。

**Q：为什么配置页里有些选项看不到？**
A：多数字段是**按条件显示**的：TTS 推理细节要在「隐藏高级 GSV 参数」关闭时才出现，采样参数要先打开「启用 LLM 采样参数」，插件系统、软件更新等开关要先打开对应总开关（这些都在页面最底部的「更多」里）。这是正常行为。

**Q：为什么没有自动启动 TTS？**
A：请确认在 `config.json` 中 `auto\_start\_tts` 为 `true`，且 `tts\_start\_script` 路径正确。

**Q：主动消息 / 待办 / 工具调用等功能为什么不生效？**
A：请在「配置文件」页面开启对应的功能开关（如 `proactive\_enabled`、`todo\_enabled`、`tools\_enabled`），并按页面提示完成相关数据配置。

**Q：RAG 上传 PDF 失败？**
A：PDF 解析需要额外依赖：`pip install pypdf`；普通文本 / Markdown / 代码文件无需额外依赖。
