# 设备状态

在 QQ 里发送 `/截图` 或 `/截屏`，机器人回一张整屏截图 + 一条本机当前状态；
发送 `/录屏 10` 则录 10 秒屏幕，把视频或动图发回来。

## 触发方式

- `/截图`、`/截屏`：截 1 张。
- `/截图 3`：连拍 3 张，每张之间隔「截图时间间隔」秒，截一张发一张。
- `/录屏 10`：数字必填，表示录多久（秒），到点自动停。没带数字或不是正数时只回一句用法提示。

`#截图`、`#截屏`、`#录屏` 等价。

录屏走 `ffmpeg` 的 `gdigrab` 直接抓桌面（真视频，按「录屏帧率」抓帧），不是一张张截图拼出来的：
录 10 秒就是 10 秒，产物时长与真实录制时长一致。系统里没有 `ffmpeg` 时会退回「连拍截图再合成」，
那种方式每帧要花 0.1~0.3 秒，帧率上不去，产物也不如真录屏流畅。

走的是主程序的插件指令通道：命中后直接由插件回复，不进 LLM 管线，也不会写进对话历史。

## 回复内容

`/截图` 先发一张截图，再发一条状态文本（「回复设备状态」关掉后只发截图）：

```
【设备状态】
主机名：DESKTOP-XXXXXX
系统：Windows 11
架构：AMD64
CPU：20 个逻辑核心，当前占用 12.3%
内存：共 31.9 GB，已用 18.2 GB（57.1%），可用 13.7 GB
电源：外接电源，电量 100%
磁盘 C:\：共 255.0 GB，已用 236.7 GB（92.8%），剩余 18.3 GB
时间：2026-09-18 17:05:00
```

- 截图是整块虚拟桌面（多显示器一起截），PNG 格式。
- 系统盘：Windows 取系统所在盘，Linux / macOS 取 `/`。
- 没有电池的机器不显示「电源」这一行。
- 连拍和录屏会先回一条「开始连拍 / 开始录屏」的提示，状态文本在这一批结束后再补一条。

## 功能页设置

| 设置项 | 默认 | 说明 |
| --- | --- | --- |
| 回复设备状态 | 开 | 关掉后只发截图和录屏，不回主机名、CPU、内存这些状态 |
| 保留截图数量 | 10 张 | 截图目录里最多留这么多张（连拍的每一张也算），超出后删掉最早的 |
| 截图时间间隔 | 1 秒 | 连拍时两张截图之间等多久 |
| 录屏帧率 | 15 帧/秒 | 录屏每秒抓多少帧 |
| 录制声音 | 开 | 录屏时一起录音；GIF 动图没有音轨，只对 MP4 生效 |
| 录音设备 | 自动 | 从下拉里选一个本机录音设备；「自动」优先挑能录系统声音的回环设备 |
| 录屏格式 | GIF 动图 | `/录屏` 的产物格式，可选 MP4 视频（原分辨率，文件小得多） |

## 网页版状态面板

插件卡片上除了「打开功能页」，还有一个「打开webui」：一个独立的网页界面，
显示本机状态文本和最近 12 张截图的缩略图（点开看大图），带一个「刷新」按钮。

数据来自插件写在 `data/status.json` 里的快照 —— 每次截图、连拍、录屏结束后刷新一次，
所以面板上看到的是**最近一次操作后**的状态；刚装完还没截图时先发一次 `/截图` 或 `/录屏`。

### 录音录的是什么

录音走 ffmpeg 的 `dshow`，录的是**一个音频输入设备**，默认自动挑（优先「立体声混音」这类回环设备）：

- 想录**系统声音**（扬声器里正在放的），机器上得有回环设备 —— 「立体声混音」（Realtek 声卡可在
  声音设置 → 录制 → 显示禁用的设备里启用）或虚拟声卡（VB-Cable 之类）。没有的话录不到系统声音。
- 没有回环设备时录到的是**麦克风**。
- 具体挑中了哪个会写在日志里（`录屏同时录音：<设备名>`）；填错设备名时日志会列出所有可用设备名。
- 录音失败不会影响录屏：会再录一次不带声音的，日志里写「录音失败，这次只录画面」。

## 截图存哪、什么时候删

- 截图（`/截图`、`/截图 N`、以及没有 ffmpeg 时的录屏帧）都落在插件数据目录的 `shots/` 下，按时间命名。
- 每批结束才清理一次，超出「保留截图数量」的按时间从早到晚删。
- `/录屏` 的产物先落在 `tmp/`，发送成功就删掉；发送失败会留在那儿，日志里有记录。

## 实现说明

- 状态里的 CPU 占用率、内存、电源走 `ctypes` 读 Windows 系统接口；非 Windows 只报核心数。
- 截图用 Pillow 的 `ImageGrab`；录屏用 `ffmpeg -f gdigrab`，MP4 走 H.264，GIF 会限到 12 帧/秒、
  宽 1280 以内再生成调色板（整屏原分辨率 GIF 又大又慢）；声音走 `ffmpeg -f dshow`（AAC），只进 MP4。
  ffmpeg 按插件环境自带的 `imageio_ffmpeg` → 系统 PATH 的顺序找；都找不到时录屏退回「连拍截图再合成」。
- 插件桥接只提供文本和语音，发图片/视频是复用主程序已连上的 NapCat 客户端
  （`__main__.napcat_client`）自己组 `Image` / `Video` 消息段；拿不到客户端时只发状态文本，并在文本末尾标注。
- 连拍和录屏在后台线程里跑，不会卡住主程序的收消息和回复。
- 因此安装时的安全扫描会出现 `ctypes.windll`、`subprocess` 这类提示，属预期。

## 安装

把 `device-status` 目录放进 `%LOCALAPPDATA%\Lovomo\plugins\`，或在 WebUI 的「插件市场（测试版）」页上传 `device-status.zip`。
