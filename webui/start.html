配置文件

每份配置文件是一套完整配置，接入方式可各选一份。default 即主配置，不可删除或重命名。 接入方式列表属于主配置，不随配置文件切换。 密钥与密码只在设置页管理，本页不改动。

接入方式

三种接入方式可同时启用；保存后几秒内自动重连，无需重启。

模型服务

模型的接口地址、API Key 与模型名在此统一配置，全局生效。 配置文件页与聊天测试仅选择服务；密钥保存后只显示打码预览，密文存于 data/model_library.json。

角色管理

角色的人设、提示词、语音目录与默认情绪在此维护；配置文件页选择启用的角色。 这里改动保存后立即热生效。

角色档案

将人设、记忆、好感与心情打包为 JSON 档案导出，或在其他机器导入（可覆盖同名角色）。

插件市场

插件可加新功能或换外观，安装前自动安全扫描， 高危插件需确认后才会安装。
已装插件的启用/停用与设置在左侧栏「插件」。

使用教程

按「先配通、再调优、出问题怎么查」的顺序整理。 所有功能都必须先打开对应开关才会生效。

一、每个页面的作用

1. 配置文件：所有参数与功能总开关。配置可按名字存多份，各接入方式各一份（default 为主）。保存结果显示在右下角保存按钮上方；低频开关在底部「更多」。

2. 接入方式：消息通道，一个平台一条。NapCat 填 WebSocket 地址；微信 ClawBot 与 QQ 官方机器人扫码登录。收不到回复先点「投递自检」，仅服务端收下则重新扫码登录。

3. 插件市场（测试版）：管装插件—— 上传自己的 .zip 包、打开插件目录、刷新在线市场；自己写的插件也用这一页的 「发布到市场」上架。 安装前自动安全扫描，高危插件需确认后安装。

4. 插件：管已装插件——所有安装的插件都在这里， 可启用/停用/卸载；带功能页的插件点卡片空白处进入设置； 点插件名进其 webui 页（无 webui 则进功能页）。 左侧栏「插件」下会展开名单，只列带 webui 的插件名， 点名字直接跳转该插件页面。 右下角「检查插件更新」列出新版本插件并一键替换。

5. 聊天记录：查看/管理会话与历史，可单会话或整包导出导入。

6. 聊天测试：不开 QQ 也能直接对话，链路与真实消息一致；存于独立测试会话，「清空测试对话」会连同心情、好感与承诺一起清掉。

7. 情绪音频：每个情绪文件夹 = 一套参考音频，每段音频可单独填写它念的文字；上传后可试听。

8. 定时任务：自定义定时消息、节日/生日问候、待办提醒。

9. 统计面板：消息量、情绪分布、角色心情值与实时性能；折线图悬停显示该列各曲线的颜色与数值。

10. 高级功能：表情包、工具调用、知识库 RAG、用户画像、自主学习。

11. 日志输出：排查问题第一现场，详见第五节。每行以 [时:分:秒.毫秒][来源][级别] 开头；INFO 白色、WARN 黄色、ERROR 红色。

二、最小可用配置

1. LLM 接口：在「LLM 大模型」里选对接口类型。 本地 Ollama 用 ollama；LM Studio、llama.cpp（llama-server，地址要带 /v1）、 vLLM、云端 API 一律用 openai。服务地址、模型名要与你的服务完全一致。

2. TTS：「TTS 服务与模型」里选本地还是云端。本地填 GPT-SoVITS 服务地址（默认 http://127.0.0.1:9880）、 模型目录、参考音频根目录，文本语言要与参考音频的实际语言一致；云端填服务商地址、模型与音色。

3. 情绪音频目录：参考音频根目录下的每个子文件夹就是一个情绪 （如 pingjing、gaoxing），文件夹里放参考音频，文字按音频同名 txt 填写 （可用「一键识别」自动生成；某段音频没单独填写时，用文件夹里的 asr.txt， 再没有就用配置里的「默认参考音频文本」兜底）。 模型/其他杂物目录不会被误识别成情绪。

4. 语音识别：同一套设置还负责把用户发来的语音转成文字， 位置在「配置文件 → 更多 → 语音识别」：本地走 GPT-SoVITS 自带的 ASR，线上走 DashScope。

5. 验证：保存配置后看日志——启动时会打印 LLM 连通性探测结果、扫到的情绪数量、 调度任务注册情况。级别为「警告」或「错误」的行先解决，再谈调优。

三、参数怎么调（按效果分类）

· 回复太长/太慢：「历史消息条数」控制模型能看到的对话长度（默认 8）； 「回复生成超时」别设太小。

· 语音与文字对不上、语音少了某个词： 打开「TTS 详细日志」，日志会分别打印LLM 交过来的完整台词与实际送去合成的文本。 两者内容字不一致时日志会明确写出「清洗前后内容字不一致」。 「交叉渐变长度」不要超过单句时长。

· 语音把动作、表情、场景也念出来：打开「TTS 台词清洗与日志」里的 「移除非台词内容」（默认开）。括号里的动作、表情与颜文字只留在文本， 不进语音；引号里的台词不受影响。

· 情绪老是"平静"：打开「情绪判定规则引导」（默认开）。 也可以填「自定义情绪判定补充规则」， 例如"只要主人夸我可爱，就必须用 haixiu"。

· 难度调高以后她还是很难靠近：设计如此。想让她好说话就调「简单」，想保留好感节奏就调「普通」。

· 角色漏回消息：检查「回复审判与心情」——这两个是独立开关： 「LLM 判断是否需要回复」可能让模型直接不回； 「记录角色心情值」只更新心情，不会拦任何回复。 想保留心情值又不想漏回消息：只开心情值、关掉回复审判。 心情值影响回复概率的参数仅在两个开关都开时显示。

· 主动消息/节日问候话题对不上： 「主动消息/问候携带的历史条数」（默认 6）把最近几条对话发给模型， 更早内容用摘要压缩，建议同时打开「对话上下文自动摘要」。 设为 0 则不携带历史。

· 微信里收不到机器人的回复：聊天记录页能看到回复，说明 App 已发出； iLink 服务端可能收下请求但不投递，日志里的 sendmessage 仍然显示 ret=0， 去「接入方式」重新扫码登录一次即可重建绑定， 恢复后先发一条消息试试。

· 主动消息从来不发：确认「主动消息（闲置唤醒）」已开， 并注意三个限制：闲置阈值、静默时段、单会话每日上限； 若开了「回复前不再主动」，用户没回复之前不会再开口。 启动时日志会打印"已恢复 N 个会话的闲置计时"。

· 生成了语音但没声音/半截语音：日志出现"分段音频合并已降级为…"即走了兜底路径 ；出现"TTS 合成失败"则去查 TTS 服务本身。

· 用户发的语音没被理睬 / 答非所问：对方发来的语音会先用「配置文件 → 更多 → 语音识别」 里的设置转成文字再处理；转不出时日志会写"这条语音没转出文字"： 本地通道需要 GPT-SoVITS 的 ASR 环境（首次会下载模型），线上通道需要填好密钥与模型名。

· 聊天记录里角色的回复被合并成一整段：开启「分开发送」后，QQ 里发了几条， 记录页就记几条；关闭时按整段记一条。气泡颜色可区分角色与不同用户。

四、工具调用

1. 总开关：「工具调用」分组里的「工具调用 (Function Calling)」； 每个工具还要在「高级功能 → 工具调用」里单独启用。

2. 触发方式怎么选： 关键词门控最稳，但口语化请求可能漏； LLM 自主判断先判断消息是否需要客观信息（时间/计算/天气/搜索/链接等）， 闲聊消息直接跳过工具流程； 全部放行不做门控，模型可能什么都调，一般不建议。

3. 天气：用户没说地点时，角色不会自己猜一个城市。 想让它在用户没说地点时也能查，请在工具编辑里填「默认城市」。

4. 安全搜索：三档。 无不限制；一般（默认）允许 R16+ 站点但过滤 R18 内容； 严格连低俗、暗示的站点与内容一并过滤。 给支持安全搜索的引擎（SearXNG/Bing/Google News/Brave）带上相应参数。 结果变少属正常，日志会写明过滤了几条。

5. "搜索只出来前几条/像被截断"：一次搜索给模型的全部结果受 「搜索总字数预算」限制（默认 4000 字），超预算的结果会被整条省略 ，并在结果里注明"因长度限制省略 N 条"。 想看到更多条：把「每次搜索返回条数」和「搜索总字数预算」一起调大 （条数 × 每条约 300 字 ≤ 预算），或在「显示完整日志」下查看——完整模式不会被截断 （极端情况有 40 万字符兜底上限）。

6. 工具输出在日志里看不全：把「工具输出日志字数上限」设为 0（默认）即为完整输出。

五、出问题了怎么查（按现象对照）

· 完全没有回复：先看日志有没有"收到私聊/群聊 …"。 没有 → 检查 NapCat 连接与「群聊需要@才回复」；有 → 看后面是"回复审判决定不回复"还是请求超时。 识图失败会降级为普通文本回复，日志里会写"识图失败，降级为普通文本回复"。

· 回复和上一条对不上/像没看到图：图片若被判定为"无需回复"，系统仍会把画面描述写进历史， 用户随后追问时会重新识图；日志里会有 "本条消息指向刚才那张未被真正看过的图片"的提示。

· 待办提醒内容很怪（例如提醒"再提醒我"）： LLM 提取模式会结合最近对话还原真正事项（如"睡觉"）； 正则模式无上下文，空指令会被丢弃（日志有记录）。 想更准就把「待办提取方式」设为 llm。

· 提醒时间不对：绝对时刻（"23点"）由本地解析成"最近一次到来的该时刻"， 日志会打印解析结果与触发时刻，可直接核对。

· 补发问候没有发生：日志里搜索"问候补发"。 常见原因：程序启动时还没到问候时刻、处于静默时段、事件没有目标会话、 或等待 NapCat 连接超时（可调「补发等待 NapCat 的超时」）。

· 日志怎么看：每行都以 [时:分:秒.毫秒][来源][级别] 开头， 来源是 Lovomo 或 [插件]，级别是 INFO、WARN、 ERROR；界面按级别着色， 和 app.log 里写的是同一套前缀。 默认"精简模式"（只回尾部若干行）；勾选「显示完整日志」看全部输出。 排查时建议打开它，并按关键词搜索：回复审判、工具调用、 搜索预取、回检、待办提取、问候补发、TTS。

· 日志文件：程序日志同时写入 app.log（程序目录；装到只读目录时在 %LOCALAPPDATA%\Lovomo）。文件超过「日志文件大小上限」（默认 5 MB）时， 会自动丢弃最早的记录。

六、几个容易被忽略的联动关系

· 回复概率门控只在「回复审判」开启时生效；只开心情值时不会影响回复。

· 主动消息/问候的历史承接依赖会话里已有记录，全新会话等于没有上下文。

「识图自动收藏表情」需同时开启「表情包功能」；无明确判定时默认不收藏。

「分开发送」关闭时，「语音分开发送」「文本分开发送」等选项会自动隐藏。

黑话词典全角色共用：只收通用写法，含角色名或仅单次对话成立的说法不入库， 已有的这类旧词条会移进「待确认」。

用户画像昵称默认取对方 QQ 昵称，自动提取不改写，对方明确要求才变。

会话摘要更新后会复核一遍（每会话最多每 10 分钟一次，日志搜"回检"）： 检查关系确认、画像遗漏、新词条；只补漏不改写。

待办提取的「触发关键词」是门槛：消息不含任一关键词就不会被提取， 删掉「叫我」会导致"8点半叫我起床"这类消息被跳过。

· 问候、每日陪伴检查、主动开口这几件事会排队执行： 保证一次发多条时每条都有语音。

心情日记按当天真实对话来写，没有对话就不写；写好后发给对应用户/群， 角色不会主动提这件事。

「攻略进度」的好感只是熟悉程度；定关系还看好感以外的东西， 单方面送礼、说情话不会直接推进关系。
